# Projects Screen and Project Settings Bugs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the project-settings bugs from upstream #361, add a Projects screen (#82) and make Collection Settings say where each value comes from.

**Architecture:** Registry fixes live in `src/lib/project-registry/` (pure functions + the manager) with one new Rust command to check folders exist. Collection folder overrides are passed to Rust as a `name → folder` map so scanning, deep-link resolving and the watcher all use the same folders. The Projects screen is a dialog opened from a `uiStore` flag (welcome screen, File menu, command palette). Settings legibility is a pure `describeCollectionSettings` in `lib/project-registry/` rendered by `CollectionSettingsPane`.

**Tech Stack:** Tauri 2 (Rust, tauri-specta), React 19, Zustand 5, TanStack Query 5, Vitest, shadcn/Base UI.

**Spec:** the brief (`.superpowers/sdd/2026-11-04-four-features/shared-brief.md` + the feature brief) and upstream issues #82, #361.

## Global Constraints

- Zustand selectors only, `getState()` in callbacks, no default `useMemo`/`useCallback`, React-Compiler-compatible, semantic colour tokens only.
- Regenerate `src/lib/bindings.ts` when commands change (`cd src-tauri && cargo test export_bindings -- --ignored`).
- UI copy short and plain: "folder", "file name", no jargon.
- Don't add the #87 filename-pattern setting; don't redesign the settings storage model.
- Commits: plain messages, no trailers. Don't push.
- `bun run check:all` exits 0 at the end.

## Review Focus

- Two copies of one template (same package name), both folders present: each keeps its own registry entry and settings (Task 1 test).
- Project moved (old folder gone, same package name): keeps its ID and settings (Task 1 test).
- Folder with no `package.json` opened next to a registered one of the same folder name: new entry (Task 1 test).
- Preferences file with invalid JSON: copied to `<name>.broken-<timestamp>.json`, defaults written once, user told once (Task 4 test).
- Collection folder override pointing at a folder outside `src/content`: collection found there and watched (Task 2 Rust tests).
