# Grammar and spell checking (Harper) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Underline spelling and grammar issues in the body text as the writer types, with suggestions, Ignore and Add to dictionary, and settings in Preferences.

**Architecture:** `harper-core` (pinned `=3.0.0`) runs in Rust behind one tauri-specta command, `check_grammar`, on a blocking thread. Rust masks MDX-only syntax, lints with Harper's Markdown parser, drops overlaps and dictionary words, and returns issues with UTF-16 offsets. The frontend feeds the command from `@codemirror/lint`'s `linter()` (debounced, stale results discarded) and maps issues to diagnostics with actions.

**Tech Stack:** harper-core 3.0.0 (Rust), @codemirror/lint 6.9.x, React 19, Zustand 5, Vitest, cargo test.

**Spec:** the feature brief (grammar section of `.superpowers/sdd/2026-11-04-four-features/shared-brief.md` in the main checkout) and dannysmith/astro-editor#265 (maintainer's research comment).

## Spike result (decides the path)

- harper.js 3.0.0 is a 94 MB npm package (about 18 MB of WASM), needs `wasm-unsafe-eval` in the CSP and a worker in WKWebView, untested in Tauri.
- harper-core 3.0.0 in Rust, 5,500 words of Markdown: 45 ms per lint (release), 70 ms in dev with Harper's crates optimised (560 ms without), 300 ms one-off setup. HTML/JSX is unlintable to Harper, code and URLs are skipped; MDX `import` lines and `{expressions}` produce noise, and text inside a block-level component isn't checked.
- Chosen: Rust. No WASM in the bundle, no CSP change, fits "Rust does the heavy work".

## Global Constraints

- Pin `harper-core = "=3.0.0"` with `default-features = false, features = ["concurrent"]`.
- Grammar checking on by default; dialects American (default), British, Canadian, Australian, Indian.
- Dictionary lives in app data (global settings), never in the project.
- Colours only through tokens in `src/App.css`; quiet underlines; spelling and grammar differ subtly.
- Zustand selectors only, `getState()` in callbacks, `lib/` never subscribes, no new `useMemo`/`useCallback`.
- Plain UI copy. Commit messages plain, no trailers. `bun run check:all` exits 0.

## Review Focus

- Non-ASCII text (curly quotes, emoji, accents) before an issue: underline must sit on the right word (Rust test with emoji + accent; TS test not needed because Rust returns UTF-16).
- Typing while a check is in flight: results for an old document must not land on new text (linter discards when `doc` changed; covered by @codemirror/lint itself, verified in app).
- MDX component tags, `{expressions}`, `import`/`export` lines: no underlines in them, but prose between component lines is still checked (Rust tests).
- A word added to the dictionary in any case ("Astro" vs "astro") stops being flagged (Rust test).
- Turning checking off clears underlines at once; switching dialect re-checks ("colour" flagged in American, not British) (Rust test for dialect; app check for toggle).

### Task 1: Rust grammar engine and command

**Files:**
- Create: `src-tauri/src/grammar/mod.rs` (engine, masking, offsets, tests)
- Create: `src-tauri/src/commands/grammar.rs` (command + managed state)
- Modify: `src-tauri/Cargo.toml` (dependency, dev-profile opt-level for harper-core, harper-brill, fst), `src-tauri/src/lib.rs` (mod + manage), `src-tauri/src/commands/mod.rs`, `src-tauri/src/bindings.rs`, `src/lib/bindings.ts` (regenerated)

**Interfaces — Produces:**
- `commands.checkGrammar(text: string, fileType: GrammarFileType, dialect: GrammarDialect, dictionary: string[]) => Promise<Result<GrammarIssue[], string>>`
- `GrammarFileType = 'md' | 'mdx'`, `GrammarDialect = 'american' | 'british' | 'canadian' | 'australian' | 'indian'`
- `GrammarIssue { from: number, to: number /* UTF-16 */, rule: string, kind: 'spelling' | 'grammar', problem: string, message: string, suggestions: string[] /* replacement text for from..to; "" = remove */ }`

Rust pieces in `grammar/mod.rs`: `mask_mdx(chars: &[char]) -> (Vec<char>, Vec<(usize, usize)>)` (replace ESM lines, JSX tags incl. multi-line, `{…}` expressions with spaces, keep newlines, return masked char ranges); `char_to_utf16(chars) -> Vec<usize>`; `Checker { dialect, words, dict, group }` with `Checker::new(dialect, words)` and `check(&mut self, text, file_type) -> Vec<GrammarIssue>`. `kind` is `spelling` for `LintKind::Spelling`, else `grammar`. Overlaps: sort by (start, priority), keep first. Drop issues touching masked ranges or whose `problem` equals a dictionary word ignoring case. Suggestions: `ReplaceWith(s)` → s, `InsertAfter(s)` → problem + s, `Remove` → "", deduplicated. Command state: `GrammarState(Mutex<Option<Checker>>)`, rebuilt when dialect or words differ; work in `spawn_blocking`.

- [ ] Write tests: `flags_misspelling_with_suggestion` ("This is teh test." → kind spelling, suggestions contain "the"); `utf16_offsets_after_emoji_and_accent` ("Café 🎉 teh end" → from/to select "teh" in UTF-16); `skips_code_and_urls`; `mdx_masks_imports_tags_and_expressions` (no issues inside `import … '../x.astro'`, `<Callout title="Heads upp">`, `{frontmatter.titel}`); `mdx_checks_text_between_component_lines` ("<Callout>\nThis are wrong.\n</Callout>" → an issue on "This are"); `dictionary_word_is_not_flagged` (add "Kevvin", text "Kevvin and kevvin" → none); `dialect_changes_spelling` ("colour" flagged american, not british); `overlapping_lints_keep_one`.

### Task 2: Settings and lint mapping in `lib/`

**Files:**

**Interfaces — Produces:**
- `GrammarSettings { enabled?: boolean; dialect?: GrammarDialect; dictionary?: string[] }`
- `resolveGrammarSettings(global?: GlobalSettings | null): Required<GrammarSettings>` (defaults on / american / [])
- `GRAMMAR_DIALECTS: { value: GrammarDialect; label: string }[]` (labels "American English", "British English", "Canadian English", "Australian English", "Indian English")
- `addWord(words: string[], word: string): string[]` (trimmed, no case-insensitive duplicates, sorted); `removeWord(words, word): string[]`
- `ignoreKey(doc: string, issue: GrammarIssue): string` (rule + problem + up to 20 chars either side on the same line)
- `ignoreIssue(filePath: string, key: string)`, `isIgnored(filePath, key): boolean` (session-only, per file)
- `plainMessage(message: string): string` (backticks → curly quotes)
- `issuesToDiagnostics(doc: string, issues: GrammarIssue[], filePath: string, handlers: { onIgnore(key), onAddWord(word) }): Diagnostic[]` (drops ignored, clamps to doc length, actions: one per suggestion labelled with the text or "Remove", then "Ignore", then "Add to dictionary" for single-word spelling issues; `markClass` `cm-grammar-spelling` / `cm-grammar-grammar`; severity `warning`/`info`)
