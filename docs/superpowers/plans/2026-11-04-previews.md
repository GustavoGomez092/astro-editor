# Site previews Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every registered site a preview image for the Home screen: a screenshot of its home page as it runs locally, or its share image until there is one.

**Architecture:** A Rust module `src-tauri/src/previews/` owns lookup (`share.rs`), image work (`thumb.rs`), storage (`store.rs`, `app_local_data/previews/`), the one-at-a-time guard and the capture flow (`capture.rs`), and the hidden capture window plus WKWebView snapshots (`window.rs`, using `snapshot.rs` moved out of the debug-only agent bridge). Commands in `commands/previews.rs`. Triggers: a dev-server state listener in `lib.rs` (server became ready), a registry-write hook (cleanup), and one fire-and-forget call in Open from GitHub after preparing.

**Tech Stack:** Rust, Tauri 2.12, objc2-web-kit (WKWebView snapshots), `image` 0.25 (jpeg/png/webp), tempfile in tests.

**Spec:** `/Volumes/Content/projects/astro-editor/.superpowers/sdd/2026-11-04-four-features/home-brief.md` (section P and the Contract).

## Global Constraints

- Contract names are binding: `projectPreview(projectPath)`, `captureProjectPreview(projectPath)`, `ProjectPreview { kind: 'screenshot' | 'share-image', src: data: URL JPEG ≤ 800 px wide, takenAt: ISO | null }`, event `project-preview-updated` with `{ projectPath }`.
- Capture window: own label, 1440×900, invisible (on screen, transparent, click-through) and unfocused, loads only `http://localhost:<port>/`, no IPC or capabilities, other navigations, new windows and downloads blocked, never remote.
- One capture at a time; 45 s overall timeout for the capture (never shot sooner than 5 s after load and fonts); the window is always closed.
- Stored as `previews/<project id>.jpg` in app local data, with its time.
- Automatic capture on server ready at most once an hour per project; only when the publishing tools are on.
- No site-specific hacks. Clippy `-D warnings`, `format!("{x}")`. Commits: plain messages, no trailers.

## Review Focus

- A site that never stops animating (WebGL, marquee): the settle wait must end at its cap and still take the picture.
- A project path not (yet) in the registry: capture must not store an orphan file; `projectPreview` falls back to the share image.
- The dev server fails or is stopped mid-capture: error returned, window closed, guard released.
- A share image that's huge, a different format than its extension, or corrupt: thumbnail or `None`, never a panic.
- A server the user started must never be stopped by a capture.

### Task 1: Share image lookup and thumbnails

**Files:** Create `src-tauri/src/previews/share.rs`, `src-tauri/src/previews/thumb.rs`; modify `Cargo.toml` (`image = { version = "0.25", default-features = false, features = ["jpeg", "png", "webp"] }`).

**Interfaces — Produces:**
- `share::find_share_image(project: &Path) -> Option<PathBuf>`: first existing of `public/og.{jpg,jpeg,png,webp}`, `public/opengraph-image.*`, `public/social.*`, `public/share.*` (same extensions, in that order).
- `thumb::thumbnail_jpeg(bytes: &[u8]) -> Result<Vec<u8>, String>`: decodes (format guessed from content), downscales to ≤ 800 px wide keeping aspect (never upscales), JPEG quality 82.
- `thumb::data_url(jpeg: &[u8]) -> String` (`data:image/jpeg;base64,…`).

Tests: lookup order and missing → None; 1600×1000 → 800×500; 400×300 stays 400×300; garbage bytes → Err.

### Task 2: Storage, cleanup and `projectPreview`

**Files:** Create `src-tauri/src/previews/store.rs`; modify `commands/previews.rs`, `commands/files.rs` (registry write hook).

**Interfaces — Produces:**
- `store::project_id(preferences_dir, project_path) -> Option<String>` (registry lookup by path, trailing slash ignored).
- `Store { dir }` with `save_screenshot(id, jpeg, taken: SystemTime)`, `screenshot(id) -> Option<ProjectPreview>` (takenAt from the file's mtime), `share_thumbnail(id, source: &Path) -> Option<ProjectPreview>` cached as `<id>.share-<mtime secs>.jpg`, older ones removed, `taken_at(id) -> Option<SystemTime>`, `prune(keep: &HashSet<String>) -> usize` (removes files whose id isn't kept).
- `lookup(store, preferences_dir, project_path) -> Option<ProjectPreview>`: screenshot, else share thumbnail, else None. A project not in the registry gets only the share image, uncached.

Tests: save then read; share thumb cached and replaced when mtime changes; prune keeps registered ids; lookup order.

### Task 3: One-at-a-time guard and capture flow

**Files:** Create `src-tauri/src/previews/capture.rs`.

**Interfaces — Produces:**
- `CaptureGuard` (managed state): `try_begin() -> Option<CaptureTicket>`, ticket drop releases.
- `capture_flow(ctx: &impl CaptureEnv, project_path) -> Result<Option<ProjectPreview>, String>`: checks the tools are on, takes the guard (busy → Err "A preview is already being taken."), starts the server if not running/external and remembers it did, waits for running (install allowed, up to 5 min), captures via `CaptureEnv::snapshot(port)`, stores, emits, stops the server only if it started it and nothing else changed it — always, even on error.
- `CaptureEnv` trait (server state/start/stop, snapshot, store, emit) so the flow is testable without Tauri.
- `should_auto_capture(last: Option<SystemTime>, now) -> bool` (≥ 1 h).
- `port_of(url: &str) -> Option<u16>`.

Tests with a fake env: busy guard, starts-and-stops, leaves a running server alone, stops even when the snapshot fails, hour gate, port parsing.

### Task 4: Capture window and release-safe snapshots

**Files:** Move `agent_bridge/snapshot.rs` to `src-tauri/src/snapshot.rs` (release-safe, adds `snapshot_png(window, width: Option<f64>)`); create `src-tauri/src/previews/window.rs`; modify `lib.rs` (invoke handler refuses the preview window's label).

- Window: label `site-preview`, 1440×900, built `visible(false)` then ordered on screen transparent and click-through (a hidden page freezes animations), `focused(false)`, every request but its own localhost port blocked, `on_navigation` same origin only, `on_new_window` deny, `on_download` deny, `on_page_load` finished → signal.
- Settle: after load and fonts, always wait 5 s, then until 4 small snapshots in a row match (at most 10 s more, or 20 s after load); overall 45 s with 5 s kept for the picture; then a full snapshot → `thumbnail_jpeg`. Window closed by a drop guard.
- Verified in the dev app on a scratch copy of Kevin's site: the image shows the hero.

### Task 5: Triggers, cleanup wiring, docs

- `lib.rs`: dev-server listener → on `running`/`external` with a URL, spawn an automatic capture if `should_auto_capture` and the guard is free. Prune at startup and after `write_app_data_file` of `preferences/project-registry.json`.
- `OpenFromGitHubDialog.tsx`: after `setProject`, `void commands.captureProjectPreview(projectPath)` when prepared.
- `docs/developer/site-previews.md`, link in `AGENTS.md` docs list; `agent-tooling.md` if the snapshot module path is mentioned.
